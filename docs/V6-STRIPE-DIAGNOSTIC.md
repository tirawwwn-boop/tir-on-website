# Diagnosticul plății 4242 pe instalarea V5

Cauza incidentului de pe tir-on.ro este nedeterminată. Începe cu dovezile încercării existente. Saltul de la pagina de checkout la o eroare generică nu indică singur dacă s-a creat, confirmat sau debitat un PaymentIntent.

1. Notează ora exactă, fusul orar, suma, metoda (card introdus manual sau express), versiunea WooCommerce și versiunea gateway-ului. Verifică în **WooCommerce → Comenzi** dacă există o comandă la acel moment. Citește notele de comandă, metoda, starea și identificatorul PaymentIntent dacă există. În Stripe **Test mode → Workbench → Logs / Payments**, verifică aceeași fereastră de timp și același cont. Dacă există un intent reușit, reconciliază-l cu acea comandă înainte de a repeta încercarea.
2. În **WooCommerce → Stare → Jurnale**, selectează ziua și sursa **woocommerce-gateway-stripe**, apoi **fatal-errors** și, dacă există, **place-order**. Caută prima excepție, prima cerere respinsă și codul HTTP. Dacă lipsesc detaliile, activează temporar jurnalizarea din setările avansate ale gateway-ului Stripe pentru o singură încercare TEST autorizată. Consultă și **cPanel → Metrics → Errors**, logul PHP al domeniului și evenimentele ModSecurity prin Hostico. Păstrează afișarea erorilor PHP dezactivată pentru vizitatori.
3. La o reproducere controlată, deschide fila Network, păstrează jurnalul și urmărește **?wc-ajax=checkout**, apoi cererile extensiei Stripe. Notează statusul, tipul răspunsului și câmpul JSON result. Un HTML de autentificare, un avertisment PHP înainte de JSON, 403/WAF, 500/PHP sau 503 poate declanșa mesajul generic din JS. Un HTTP 200 cu result=failure cere citirea mesajelor de validare. Exclude coșul, checkout-ul, pagina Luna, wc-ajax și sesiunile Woo de la cache integral. Nu exporta HAR-ul brut și nu dezactiva protecțiile.
4. **Fără cerere la Stripe** — verifică tariful disponibil pentru adresa RO, telefonul obligatoriu, sesiunea și accesul PHP la directorul privat. La crearea liniei, TIR-ON verifică semnătura articolului și copiază fotografia în orders/. Înainte de plată verifică din nou copia finală. O imagine expirată, lipsa spațiului/inodurilor, permisiuni greșite sau open_basedir pot opri comanda. Încarcă o imagine sintetică nouă pe staging și verifică accesul în Atelier. Blocarea concurentă a sesiunii în cart-orders.php expiră după 5 secunde și poate da 503 la solicitări paralele. Nu șterge lock-uri ori fotografii din producție. Un 503 cu alt răspuns poate proveni și de la hosting.
5. **Cerere la Stripe, fără plată confirmată** — verifică întâi operația și răspunsul în Workbench (de exemplu payment_intents, payment_methods, codul de eroare, starea requires_action). Verifică dacă cheia publică, cheia secretă/restricționată și contul conectat aparțin aceluiași mediu TEST. Garda TIR-ON admite gateway-ul oficial UPE cu identificatorul stripe, chei TEST valide și un cont cu charges_enabled; protecția HTTP verifică Basic/Bearer TEST. Instalarea locală a gateway-ului folosește Basic cu cheia și două puncte. Afișarea Elements explică doar inițializarea clientului. Pentru portofele verifică separat identificatorul trimis și dacă sunt prezente telefonul și adresa. Endpointul express de adăugare directă a produsului este blocat intenționat pentru a impune personalizarea.
6. **Intent reușit, comandă neconfirmată** — verifică răspunsul imediat al extensiei, apoi **Workbench → Webhooks → Event deliveries**. Compară evenimentul TEST și endpointul indicat de plugin (wc-api=wc_stripe), ora și codul de răspuns. TIR-ON cere POST, eveniment cu livemode=false și secretul de webhook TEST configurat. Extensia oficială verifică semnătura. Un 401/403 poate proveni și din Directory Privacy/WAF, iar webhook-ul blocat poate lăsa starea nesincronizată. Nu retrimite plata pentru a repara un webhook.
7. Pe Hostico lasă **TIRON_ENABLE_TEST_CHECKOUT=false**. Constanta controlează exclusiv simulatorul care cere și mediu local și un fișier exclus din ZIP. Nu activează gateway-ul Stripe. Păstrează verificarea semnăturilor, protecția foto și cheile LIVE dezactivate.

Pentru diagnostic transmite numai versiuni, oră, ID intern de comandă, stare, cod HTTP/eroare, identificator de solicitare Stripe și fragmentul redactat al primei erori. Omite chei API, client_secret, order key, antete de autorizare, cookie-uri, corpuri brute, date de card, adrese și fotografii. După verificare revino la nivelul anterior de jurnalizare.

După o eventuală instalare V6, sursa suplimentară **tiron-checkout** înregistrează ramurile session_lock_timeout, order_photo_copy_failed și order_photo_unavailable. Ultima include ID-ul intern de comandă. Aceste marcaje nu existau pe V5. Absența lor nu demonstrează că Stripe a acceptat plata. Testul local a verificat exclusiv compatibilitatea constructorului de antete al gateway-ului cu garda HTTP, folosind o valoare TEST sintetică și una respinsă, fără emiterea vreunei cereri către Stripe.
